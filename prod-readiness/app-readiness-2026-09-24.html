  • Add peer-review gate to release process: Require a PR review to main before cutting a release tag. Prevents accidental or untested releases. (EA-1)

Next sprint

  • Formalise performance baselines: Run a timing benchmark for the 3 most expensive operations (graph-sync on a 50-module repo, setup-init, code-review --full). Document in architecture-deployment.md. (EA-5)
  • E2E skill scenario test for the ICEA happy path: Extend tests/skill-scenarios/ with a fixture-driven test that validates the icea-feature → SAVE PLAN → SAVE ICEA → APPROVE → icea-implement flow produces the expected file artifacts. (EA-8)

Strengths — What Is Already Well-Implemented

  • Well-structured ADO pipeline — Two-stage pipeline (CI for branches/PRs, ReleaseValidation for tags) with structural validation, Jest suite, c8 coverage, npm audit, and version consistency checks. JUnit results published. Pipeline comments explain the release flow clearly.
  • Hook-based enforcement architecture — ICEA floor, secret guard, script review gate, and context budget hooks form a layered enforcement model that operates without relying on developer discipline. The hooks are the authorization model for a local tool.
  • File-based state with git as the backup layer — No database means no migration risk, no backup schedule, and no data loss on rollback. All plugin state (graph.json, dream-init-state.json, memory/) is in git.
  • 28 test files mirroring scripts 1:1 — Strong test discipline: every script in scripts/ has a corresponding test in tests/. Migration validation and skill scenario fixtures extend coverage beyond unit level.
  • Idempotent operations throughout — setup-init, setup-sync, graph-sync, and dream are all documented as safe to re-run. This is essential for a tool that operates in an unpredictable developer environment.
  • Rollback is first-class — Re-install prior version is documented in architecture-deployment.md and the release flow (npm run bump + npm run release) creates a clean version history from which to roll back.
  • Dependency vulnerability gate in CI — npm audit at --audit-level=high blocks releases with high or critical CVEs in dependencies. This closes the supply-chain attack surface for transitive dependencies.

# Business Context Generation
_Spec version: 1.0 · Created: 2026-09-01_
_SRP owner of: identify domain → ground → synthesize → write `.claude/business-context.md`_

Single module that produces a project's domain-tailored business-context severity policy.
`architect`, `setup-init`, the `SET DOMAIN` handler, and migration Stage 0.5/0.6 all **invoke
this module** — they contain no generation logic of their own (SRP: one owner, one reason to
change).

**Inputs:** the analysing context's codebase read (architecture docs / entity + table names /
dependencies). For migration, the SOURCE inventory/architecture.
**Output:** `.claude/business-context.md` in the project root, plus a `Domain:` line in
CLAUDE.md and a `domain` field in `.claude/dream-init-state.json`.
**Write convention:** architect's `APPROVED` draft flow (draft shown → written only on the
exact word `APPROVED`) — NOT the ICEA `APPROVE ADO-{ID}` Write Gate.

---

## Step 0 — Idempotency check

If `.claude/business-context.md` exists and is populated (no `⚠ Not yet generated` marker on
line 1), do **not** clobber it. Report it exists and offer `refresh` (re-run) or `keep`. Only
proceed to overwrite on an explicit refresh + `APPROVED`. (Mirrors `arch-populated-detect.md`.)

## Step 1 — Infer + confirm domain, jurisdiction, secondary sensitivities

1. **Infer** the most likely domain from entity/table names, dependencies, and
   `architecture-data.md` (migration: from the source inventory). Map to the closest preset in
   `business-context-presets.md`.
2. **Ask ONE confirmation question** (AskUserQuestion), inferred domain pre-selected as
   Recommended:
   - **Domain:** legal / healthcare / fintech / ecommerce / govtech / generic / other.
   - **Jurisdiction:** US / EU / UK / India / multi / other — required to scope regulatory
     grounding queries.
   - **Secondary sensitivities** (optional free text): other regulated data the app handles
     (multi-domain apps) → become `(project-specific)` B-entries.
3. `other` domain → base on the `generic` seed.

## Step 2 — Resolve preset

- **Verbatim-locked domain** (e.g. `legal`): copy the locked table byte-for-byte. Grounding
  (Step 3) may only *append* `(project-specific)` entries; never rewrite locked entries.
- **Seed-checklist domain:** carry the seed's frames + example triggers forward as the
  scaffold for Step 3.
- **Migration carry-forward:** if the SOURCE already has `.claude/business-context.md`, carry
  it into the target instead of re-deriving (still run Step 0/APPROVED on the target).

## Step 3 — Regulatory grounding (best-effort)

Run `business-context-grounding.md`: spawn the **bc-searcher** subagent (`{domain,
jurisdiction}` only) → grounded, cited categories → **bc-synthesizer** subagent (grounded
facts + architecture, no web tool) → draft B-series with `citation` + `retrievalDate`.

Fallback (no network / tool-unavailable / `BUSINESS_CONTEXT_GROUNDING` off): skip grounding,
use the seed/locked table, set `web-grounded: false`. Never silently degrade — record why.

## Step 4 — Synthesize the B-series draft

Compose `.claude/business-context.md`:

```
# Business Context — {Domain} ({Jurisdiction})
<!-- generated by business-context-generation.md · domain={domain} · preset={preset}
     · web-grounded={true|false} · date={retrievalDate} -->

## B-series triggers
| # | Trigger | Why Critical | Source |
|---|---------|--------------|--------|
| B1 | … | … | {citation or "preset"} |
| …  | … | … | … |

## Secondary / project-specific
| Bk | … (project-specific) | … | … |

## Provenance
- Domain / jurisdiction: …
- Preset: … · web-grounded: … · retrieval date: …
- Citations: …
```

IDs are `B1…Bn`; length is domain-defined. This file, once present, **takes precedence** over
the neutral fallback in `business-context-severity.md`.

## Step 5 — APPROVED gate + write

Show the full draft + target path `.claude/business-context.md`; write only on the exact word
`APPROVED`. On a **verbatim-locked** domain, also show a diff of any `(project-specific)`
additions against the locked table so changes are visible.

## Step 6 — Record the domain

- CLAUDE.md: set/update the managed `Domain:` line (near the stack header).
- `.claude/dream-init-state.json`: merge `{ "domain": "<domain>", "jurisdiction": "<j>" }`
  (merge-on-write, never drop existing fields).

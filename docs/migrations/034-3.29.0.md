# Migration 034 — v3.29.0

## Summary

Syncing a project after a plugin upgrade is now **one command** (ADO-83):

```bash
cd <project root>
node "<installed plugin>/scripts/setup-sync.cjs"
```

The script does everything mechanical that `/setup-sync` used to walk through step by step:
version stamp, bootstrap in sync mode (hooks, command stubs, plugin-owned skills, plugin-path.txt,
CLAUDE.md sections, ignore file), stack re-detection and rule redeploy, the CLAUDE.md git/bash path
retry, external-stack refresh and the run record. It then lists the migration notes in range and
what still **needs Claude**. `/setup-sync` now runs this script and only handles that list.

Migration notes like this one now reach target projects: the installers copy `docs/migrations/`
into the installed plugin. Before 3.29.0 the installed copy had no `docs/` folder, so `/setup-sync`
never showed a note.

## Sync actions (idempotent — never overwrite developer content)

- None beyond the usual sync. Running `setup-sync.cjs` or `/setup-sync` once applies everything.
- The separate `/gitignore-sync` step is gone from `/setup-sync`: the bootstrap's sync mode already
  rewrites the managed block of `.gitignore` / `.tfignore`.

## Notes

- **No manual action needed.**
- Several projects: `node "<installed plugin>/scripts/setup-sync.cjs" --root=<project>` in a loop.
  Exit codes: 0 synced · 1 a step failed (fix and re-run) · 2 not set up with `/setup-init`.
- The installed plugin folder is `installPath` in `~/.claude/plugins/installed_plugins.json`.
  `.claude/plugin-path.txt` points at it again after the sync.
- No state, schema or ignore-block changes.

# Migration 030 — v3.19.0

## Summary

**Version-aware .NET detection** — per-project runtime spread + migration version-awareness, split
across one shared detection core and two independent tracks (see
`skills/shared/runtime-generation-spec.md` v1.1).

- **P1-Shared (detection engine).** `resolveDotnetGeneration` now authors a per-project `versions[]`
  spread (`path`/`role`/`tfm`|`tfms[]`/`generation`|`generations[]`), a representative `version`
  (highest deployable TFM — `Sdk.Web`/`Sdk.Worker`/`Exe`, excl. tests+netstandard), `heterogeneous`,
  `generationsPresent`, and a `packages` map (PackageReference + CPM `Directory.Packages.props`).
  `collectManifest` collects `Directory.Build.props`/`Directory.Packages.props`/`global.json`;
  effective TFM = inline → nearest props → `global.json` (sdk-derived). `repo-detect --json` = a
  recompute-and-print inspection mode that never writes state. Freshness `generations_meta`
  (`buildfile_fingerprint` + `detected_at`). Coarse `name` is unchanged (BC scalar).
- **Track B (migration — no rule-engine change).** EF Core guidance corrected (min-TFM, not a match;
  EF Core 9 runs on net8) + `dotnet-upgrade.md` scoped to modern→modern. Stage 0 detects the SOURCE
  spread (read-first from source state → `repo-detect --json` fallback), shows it in the panel, adds
  **Q1b target-version** (net8/net9/net10, default latest LTS, target≥source) with a supported-version
  hard-stop. Checkpoint bumped **1.10 → 1.11** (`mode.source_version`/`target_version`; `mode` is now
  merge-written). Stage 2 feasibility branches **posture per cluster** (modern=upgrade/removal-delta,
  framework=re-platform/parity) + ≥3-major delta warning.
- **Track A (integration/brownfield — FEATURE-FLAGGED, default OFF).** With `PER_PROJECT_RULES=1`
  (or `dream-init-state.json` `per_project_rules:true`) the rule deploy uses **scope-by-exception**:
  framework overlay rules (`csharp-framework48`/`ef6`/`wcf`/`ado-net-legacy`) get their managed
  `paths:` block regenerated to the framework project dirs; everything else deploys verbatim.
  Developer-edit protection for a scoped rule uses a **body-only hash** (`body:<hash>` in `.hashes`)
  — a machine `paths` rewrite is never mistaken for an edit, and the whole-file→body-hash
  **re-baseline** is transparent. Dry-run via `PER_PROJECT_RULES_DRYRUN=1`. The set-based generation
  gate is also flag-gated, so **flag OFF is byte-identical to pre-3.19.0** (mixed repos keep prior
  behavior — no legacy-on-modern leak). Consumer skills (icea-implement, code-review, architect) read
  `versions[]` for per-project generation/version.

## Change type

Detection-engine code (`scripts/stack-signals.cjs`, `scripts/repo-detect.cjs`) + rule-deploy code
(`scripts/setup-init-bootstrap.cjs`, behind a flag) + migration/consumer skill edits + checkpoint
schema bump (1.10 → 1.11). Backward-safe: no `versions[]` → consumers fall back to `name`; flag OFF →
deploy byte-identical.

## Required action

**Shared backfill (safe, recommended):** re-run detection so existing projects gain `versions[]` /
`packages` / `generations_meta`:
```
node {PLUGIN_DIR}/scripts/repo-detect.cjs --root=. --force
```
`setup-status` flags "version detection stale — run setup-sync/graph-sync" when `generations.dotnet`
lacks `versions[]` or the `buildfile_fingerprint` diverges.

**Track-A per-project rules (opt-in, gated):** leave OFF unless you want per-project rule scoping.
To enable, set `PER_PROJECT_RULES=1` (or `per_project_rules:true` in `dream-init-state.json`) and
first run a **dry-run** (`PER_PROJECT_RULES_DRYRUN=1`) to preview the scoped-path plan and the
one-time `.hashes` body-hash re-baseline before applying. Verify the `paths`-frontmatter injection
timing + negation-glob spike (DEVELOPER-GUIDE.md) before broad enablement. To revert: unset the flag
(pre-existing scoped rule files are treated as protected; re-deploy pristine to fully restore broad rules).

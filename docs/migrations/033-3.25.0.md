# Migration 033 — v3.25.0

## Summary

Scanners and the knowledge graph are now **multi-root aware** — they can look into the
locally-cloned dependency repos the app depends on (the curated paths in
`.claude/settings.local.json → additionalDirectories`), instead of only ever scanning the
project root. A new shared spec `skills/shared/multi-root-scan.md` is the single source of truth
for "which roots do I scan?" (`repo root + additionalDirectories`, with dedup / skip-missing /
skip-nested and an announce-before-scan convention).

Policy is **read-default, write-confirm** (no trust/classification layer — `additionalDirectories`
entries are curated, so they are treated as in-scope):

- **Read-only orientation includes dependencies by default:** the knowledge graph
  (`module-derive.cjs`, `graph-extract-edges.js`, `graph-create`, `graph-sync`) derives dependency
  modules as nodes carrying an optional, absent-tolerant `sourceRoot`, and resolves cross-root
  imports / ProjectReferences. `explain`, `icea-feature`, and `update-arch` inherit this via the graph.
- **Heavy ledger-writing scanners are opt-in:** `security`, `code-review`, `app-readiness` stay
  repo-only by default and add dependencies only with `--with-deps` (they persist FP-fingerprinted
  findings and gate `checkin` Check D — scanning unfixable dependency code every run is the wrong
  default). `checkin` invokes `code-review --changed`, which never passes `--with-deps`, so the
  commit gate stays repo-only.
- **Writes into a dependency repo always confirm:** a Write-Gate target resolving outside the repo
  root requires its own confirmation and is **not** blanketed by `APPROVE ALL ADO-{ID}` (CLAUDE.md §0
  + `write-gate-spec.md`).

## Sync actions (idempotent — never overwrite developer content)

- **Graph scripts** (`scripts/module-derive.cjs`, `scripts/graph-extract-edges.js`) and the new
  shared spec (`skills/shared/multi-root-scan.md`) ship under `PLUGIN_DIR` — picked up on plugin
  update with no per-project action. The next `/graph-sync` will discover dependency modules if
  `additionalDirectories` is populated (run `/sync-dirs` first to populate it).
- **Re-deploy the updated command stubs** into `.claude/commands/` (argument-hints gain
  `--with-deps`): `security-review`, `code-review`, `app-readiness`.
- Skills are read from `PLUGIN_DIR`, so SKILL.md behaviour changes take effect on update with no
  per-project action.

## Schema

- `graph.json` node gains an **optional, absent-tolerant** `sourceRoot` field (absolute,
  forward-slashed path of a dependency source root; absent ⇒ repo root). **`meta.schemaVersion`
  stays `"1.0"`** — a graph without the field is valid, and repo-local nodes never carry it. Follows
  the additive-field precedent in `checkpoint-schema.md` (`source_roots`).

## Notes

- **No new state keys.** The earlier trust/classification design (`external_dir_trust`,
  prompt-once) was intentionally dropped as over-engineering — `additionalDirectories` is curated by
  construction. `settings.local.json → additionalDirectories` remains a flat string array.
- **Determinism preserved:** for a single-root project (no `additionalDirectories`), graph output is
  byte-identical to pre-3.25.0. Verified via `graph-extract-edges.js` re-run diffs.

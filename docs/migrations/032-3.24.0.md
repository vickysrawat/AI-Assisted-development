# Migration 032 — v3.24.0

## Summary

Flag-taking commands now **prompt for the flag when invoked bare** instead of silently defaulting.
This resolves a contradiction between `scope-flags-spec.md` (which said "no flag → silent default
scan") and `interactive-menu-spec.md` (which said "no flag → show the menu") that let `/code-review`
and `/security-review` skip their scope menu. A new shared convention (`flag-prompt-spec.md`)
generalises the rule to every flag command. **CI / non-interactive runs never prompt** — they fall
back to the documented default.

## Sync actions (idempotent — never overwrite developer content)

- **Re-deploy the updated command stubs** into `.claude/commands/` — picked up by the command-stub
  redeploy step. Affects: `code-review`, `security-review`, `dynamic-scan`, `app-readiness`,
  `update-arch`, `graph-sync`, `graph-viz`, `gitignore-sync`, `dream-audit`, `token-analysis`
  (argument-hints + no-flag prompt notes).
- Skills are read from `PLUGIN_DIR`, so the SKILL.md behaviour changes (Step 0 prompt logic) take
  effect on plugin update with no per-project action. The new `flag-prompt-spec.md` ships under
  `skills/shared/` and is loaded on demand by those skills.

## Notes

- **Interactive behaviour change:** a bare `/code-review` (and the other flag commands) now presents
  a selection prompt with the previous default pre-selected as *recommended*, instead of running the
  default immediately. Accept the recommended option to reproduce the old behaviour.
- **CI / automation unchanged:** the prompt is skipped whenever any flag is present (including
  `--ci`), the run is headless/piped, or the skill is invoked by an internal gate. `checkin`
  (`code-review --changed`, `pr-spec-review --compact`) and `pr-create` (`--compact`) already pass
  explicit flags, so they are unaffected.
- No state/schema/ignore-block changes. `pr-spec-review` is unchanged — its callers always pass a
  mode flag.

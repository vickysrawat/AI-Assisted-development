# Migration 029 — v3.18.0

## Summary

Hardens the **migration** skill against the two ADO-9999 failure classes: **integration
misclassification** (input side) and **design-vs-as-built drift** (output side). Adds two new
migration-checkpoint stage-gates and bumps the checkpoint schema **1.9 → 1.10**.

- **Integration ground truth.** Stage 0 now extracts external-integration evidence from the host
  config (`<system.serviceModel>`/`<client>`/`<connectionStrings>`) and referenced assemblies instead
  of inferring transport/auth from consumer code. Stage 0.6 fills a ground-truth-verified **Integration
  Inventory** (new `specs/integration-verification-spec.md`); every row is a Review-Focus item and an
  `UNVERIFIED` row blocks `APPROVE INVENTORY`. New gate `stage_gates.integrations_verified`.
- **As-built reconciliation.** New gated Stage 6 Step 6.5 runs `architect` + `/graph-sync` on the
  generated code (making `.claude/architecture/*` the as-built source of truth), diffs design intent vs.
  generated code (endpoints/authz/deps/config), writes `ADO-{ID}-asbuilt-reconciliation.md`, and stamps
  the Stage 1 docs superseded (new `specs/asbuilt-reconciliation-spec.md`). New gate
  `stage_gates.asbuilt_reconciled` blocks MIGRATION COMPLETE. When golden-master is SKIPPED, this
  mechanical audit is the **required compensating control**.
- **Golden-master provided-URL capture.** Golden-master Step 1 gains a fourth branch: when the tool
  cannot self-run the source, it prompts for a **developer-provided running source base URL**, probes
  reachability, and captures against it (the strongest available oracle for WCF/IIS/Windows-auth APIs
  the AI can't launch). SKIP is now a true last resort (neither self-run nor a reachable URL).
  Multi-scheme source auth (Bearer/JWT · API-key · cookie · NTLM) from env/interactive — credentials
  are **never persisted** (only the auth *scheme*). Recorded in `decision_log.golden_master`
  (mode/url/auth_scheme/reachable/coverage), preserved across the Step 0.4 seed merge. Dev/test
  instance only; prod-looking URLs warn + require confirmation. Seed-data generation remains out of
  scope (a source-environment precondition, never fabricated).

## Change type

Migration-skill spec/step edits + 2 new specs + checkpoint schema bump (1.9 → 1.10) + 2 new
stage-gates. **No code/hook changes.** No `/setup-sync` action strictly required for existing projects
— the migration skill is plugin-shipped and read at runtime; the schema bump is backward-safe (a
resumed pre-1.10 checkpoint gains both new gates defaulted `false` at the Step 0.4 merge).

## Required action

None for provisioned projects beyond the normal version re-stamp. In-flight migrations resume safely:
the Step 0.4 seed now writes `schema_version:"1.10"` and adds `integrations_verified`/
`asbuilt_reconciled` (both `false`) without clobbering already-granted gates, `decision_log`, or
`clusters`. `/migration-status` renders the two new gates; a pre-1.10 checkpoint shows them ⬜.

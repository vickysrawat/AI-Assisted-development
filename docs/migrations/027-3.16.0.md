# Migration 027 — v3.16.0

## Summary

Makes **business-context severity domain-aware**. Previously the B1–B7 severity triggers were
hardcoded to the legal/immigration domain in `skills/shared/business-context-severity.md` and
inherited by every project. Now that spec is a domain-neutral **model + variable-length B-series
fallback**; the domain-specific triggers for a project are generated into
`.claude/business-context.md` by a new SRP module (`business-context-generation.md`), seeded from
`business-context-presets.md` and grounded in cited regulatory frameworks via
`business-context-grounding.md`. Review skills resolve **project-local first, plugin fallback**.
A new `SET DOMAIN` handler runs the generation independently of architect.

The legal triggers are **not lost** — they are preserved byte-for-byte as the verbatim-locked
`legal` preset, so an existing legal project reproduces today's B1–B7 exactly.

**Enforcement:** regulatory grounding uses two capability-separated subagents (`bc-searcher`
web-only / `bc-synthesizer` no-web) plus a deterministic PreToolUse hook
(`web-grounding-guard.cjs`) so no project data can leak into a web query. Grounding is
best-effort with a seed/offline fallback and a `BUSINESS_CONTEXT_GROUNDING` kill-switch.

## Change type

New shared specs + new plugin agents + new PreToolUse hook + settings wiring + de-legalized
shared spec + ~20 review-skill edits (B-series wording + project-local resolution). Applied by
`/setup-sync`.

## Required action

Run `/setup-sync` to deploy the new hook, wire the `WebSearch|WebFetch` PreToolUse guard and the
`BUSINESS_CONTEXT_GROUNDING` env flag, and refresh `.hashes`. Then run **`SET DOMAIN`** to
identify the project's business domain and generate `.claude/business-context.md`.

> Backfill via `SET DOMAIN` is invoked **independently of architect** — some existing installs
> skipped the architect skill, so "re-run architect" would not reach them. Until `SET DOMAIN` is
> run, reviews use the de-legalized neutral fallback (no breakage). An existing **legal** install
> selects the `legal` preset → today's B1–B7 reproduced exactly (verify via the `APPROVED` diff).

## Sync actions (idempotent — never overwrite developer content)

1. Deploy `web-grounding-guard.cjs` to `.claude/hooks/`; recompute `.hashes`.
2. Wire `PreToolUse → node .claude/hooks/web-grounding-guard.cjs --hook` (matcher
   `WebSearch|WebFetch`) and add `env.BUSINESS_CONTEXT_GROUNDING = "on"` in
   `.claude/settings.json`.
3. Add the `Domain:` header line + `SET DOMAIN` §0a handler to CLAUDE.md (managed sections).
4. If `dream-init-state.json.domain` is unset / `.claude/business-context.md` is absent, prompt
   the developer to run `SET DOMAIN`.
